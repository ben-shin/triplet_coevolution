# Security and privacy

Use synthetic inputs and a minimal reproducer when reporting an issue. If the repository offers private vulnerability reporting, use its Security tab. Otherwise contact the project owner through a previously verified private channel before sharing sensitive details. The repository currently records no dedicated security email or response-time commitment. [Repository security contact options](https://github.com/ben-shin/triplet_coevolution/security)

Local alignment, inference and offline report generation use files on your machine. Optional remote metadata providers transmit requested identifiers to the chosen service. A table of accession IDs, taxon assignments, source paths, local database names, rejected alternatives, cached responses or search logs can identify a project even without its sequences. Inspect reports, archives, journals, replay manifests and graphs before sending them elsewhere. Use local metadata or offline operation for confidential projects. Run external search tools only from an installation you trust.

Build the package from a clean checkout. Wheel and source distribution content checks examine packaged examples, public benchmark records, local report assets and executable entry points. Keep personal data outside packaging directories. Release workflows read repository contents and exercise synthetic or documented public fixtures. Dependency auditing queries public package names and exact versions. No publishing, model-upload, code-scanning upload or private-data job is configured.

Checksums help detect changes relative to a known manifest. Keep the original digest or securely transferred manifest if provenance matters. A party that can replace the files and their hash records can create another internally consistent set.
